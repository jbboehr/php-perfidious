# Development guide

Run these commands from the repository root. The build and runtime examples below cover Linux. Native Windows and
macOS builds have separate jobs in [CI](../../.github/workflows/ci.yml). The
[sampler support matrix](../SAMPLER_API.md#support-matrix) describes the available APIs on each platform.

## Build a local module

With Nix and flakes enabled, enter the PHP 8.1 development shell:

```sh
nix develop .#php81-gcc-debug
```

The shell provides PHP, its development headers, the compiler, libcap, libpfm, Composer, and Valgrind. It also installs
the repository's Git hooks. Without Nix, install PHP 8.1 or newer with matching `phpize` and `php-config`, a C compiler,
Make, Autoconf, and the Linux library development packages listed in the [source installation instructions](../../README.md#source).
Python 3 and Dash are needed for some checks below.

Build and load the module directly from the checkout:

```sh
phpize
./configure --enable-perfidious --enable-perfidious-debug --enable-compile-warnings=error
make
php -n -d extension=modules/perfidious.so --ri perfidious
```

`--enable-perfidious-debug` enables extension test hooks. It does not enable PHP's own debug or ZTS
build modes. To test a release configuration, use `--disable-perfidious-debug` instead. Run `make clean` before
reconfiguring an existing build with different flags. Use a separate checkout when switching PHP versions so that
generated files and compiled objects stay paired with the right PHP headers and executable.

## Composer, declarations, and formatting

Install the locked development dependencies and run the PHP checks:

```sh
composer install --prefer-dist --no-progress
composer validate --strict
php tools/generate-aggregate-stub.php --check
php vendor/bin/phpcs
php vendor/bin/phpstan analyze --no-progress
php vendor/bin/phpstan analyze -c tests/phpstan/aggregate.neon --level=max --no-progress tests/phpstan/aggregate.inc
php vendor/bin/phpstan analyze -c extension.neon --level=max --no-progress tests/phpstan/linux.inc
php vendor/bin/phpstan analyze -c extension.darwin.neon --level=max --no-progress tests/phpstan/darwin.inc
php vendor/bin/phpstan analyze -c extension.windows.neon --level=max --no-progress tests/phpstan/windows.inc
```

The declarations in [stubs/](../../stubs) are canonical. After editing them, regenerate `perfidious.stub.php` with
`php tools/generate-aggregate-stub.php`. The aggregate file includes every platform. The separate PHPStan runs check
each platform's declaration set, without requiring a running extension for that platform.

CI also checks that the declarations parse and the aggregate can be loaded without the extension:

```sh
php -n -l tools/generate-aggregate-stub.php
php -n -l perfidious.stub.php
php -n -l stubs/common.stub.php
php -n -l stubs/linux.stub.php
php -n -l stubs/darwin.stub.php
php -n -l stubs/windows.stub.php
php -n perfidious.stub.php
```

After entering the Nix shell, run the configured formatting and lint hooks on tracked files:

```sh
pre-commit run --all-files
```

The hook definitions live in [flake.nix](../../flake.nix). They run Actionlint, Alejandra, Markdownlint, and ShellCheck.
`.pre-commit-config.yaml` is generated by Nix. PHP_CodeSniffer checks the PHP files separately.

## PHPT tests

`make test` loads the locally built module. Start with the relevant test or directory, then run the full suite:

```sh
NO_INTERACTION=1 REPORT_EXIT_STATUS=1 make test TESTS='tests/sampler/sampler-errors.phpt'
NO_INTERACTION=1 REPORT_EXIT_STATUS=1 make test TESTS='tests/sampler'
NO_INTERACTION=1 REPORT_EXIT_STATUS=1 make test
```

`REPORT_EXIT_STATUS=1` makes a failing suite return a nonzero status. Inspect the `.diff`, `.out`, and `.log` files
beside a failing PHPT. Tests that do not apply to the current OS or build mode report a skip reason. Record those
skips when reporting results.

Linux perf-event tests need permission to call `perf_event_open()` and a usable counter source. Containers and VMs can
restrict access or expose counters that do not advance. Permission failures and zero readings need investigation even
if sampler tests pass, because the common Linux sampler uses `getrusage()` instead. See
[troubleshooting](../../README.md#troubleshooting) for the Linux access requirements.

The [public API contract test](../../tests/public-api-contract.phpt) compares the loaded extension with its platform
stubs. The Linux construction and Darwin shim tests compile temporary modules, so `cc`, `php-config`, and the tested
PHP must agree. Passing a Darwin shim test on Linux does not verify native macOS behavior.

### FPM and preload tests

The [request-handle tests](../../tests/request-handle) include local FPM fixtures that exercise repeated requests in
the same worker. They need Python 3, `proc_open()`, a shared `perfidious.so`, and a matching `php-fpm` executable beside
the tested PHP binary. The preload cases also require a non-root user and the matching OpCache shared module.

Run the group with `TESTS='tests/request-handle'`. If OpCache is outside PHP's `extension_dir`, set
`PERFIDIOUS_TEST_OPCACHE` to the absolute path of that PHP build's `opcache.so` before running the tests. Loading
OpCache in the CLI alone does not supply its path to the FPM fixture.

### Valgrind and debug hooks

Run a focused cleanup test under Valgrind with Zend's allocator disabled:

```sh
USE_ZEND_ALLOC=0 NO_INTERACTION=1 REPORT_EXIT_STATUS=1 \
  make test TEST_PHP_ARGS='-n -m' TESTS='tests/handle/memory-not-leaked.phpt'
```

Omit `TESTS` to run the full suite under Valgrind. The PHPT runner writes memory diagnostics to `.mem` files. These
checks cover the processes exercised by the runner, so a passing result does not establish that every child process
or failure path is leak-free.

Check whether the loaded extension has debug support:

```sh
php -n -d extension=modules/perfidious.so -r 'var_dump(Perfidious\DEBUG);'
```

Linux debug builds expose hooks such as `Handle::debugCloseFd()` and `Handle::debugInjectOverflowRead()` to exercise
otherwise difficult error paths. Use the existing [descriptor failure test](../../tests/handle/debug-close-fd.phpt)
and [overflow lifecycle test](../../tests/handle/debug-inject-overflow-read-lifecycle.phpt) as examples. Debug builds
also bypass the extension's `CAP_PERFMON` precheck for positive PIDs, while kernel permissions still apply. Run release
tests as well when changing capability handling.

## Configure and Nix checks

For changes to `config.m4`, run the isolated configure regression test:

```sh
python3 tests/configure-options.py
```

It requires Bash, Dash, Python 3, `phpize`, and the build dependencies. It checks twelve combinations of shell and
debug/coverage/sanitizer settings in temporary directories. It inspects generated build commands without running
instrumented binaries. If a shell is installed outside `PATH`, the script accepts its executable path through
`--dash` or `--bash`.

Nix package builds and test checks are separate outputs. For example, `nix build .#php81-gcc-debug` builds the module,
while the following target also runs PHPT and Valgrind checks:

```sh
nix build -L .#checks.x86_64-linux.php81-gcc-debug
```

The [Nix derivation](../../nix/derivation.nix) defines those checks. List the available compiler, PHP version, coverage,
and integration targets with:

```sh
nix eval --json .#checks.x86_64-linux --apply builtins.attrNames
```

Use `aarch64-linux` instead of `x86_64-linux` when selecting an output for an ARM Linux builder. Nix flakes in a Git
checkout omit untracked files, so include new source or test files in Git before testing them through a flake build.

The focused capability leak check and PHP 8.5 ZTS check have their own targets:

```sh
nix build -L .#checks.x86_64-linux.php81-gcc-capability-leak
nix build -L .#checks.x86_64-linux.php85-zts
```

The capability check verifies that the libpfm suppression still exposes an unrelated allocation leak. The ZTS check
runs CLI tests using a ZTS PHP binary. It does not exercise concurrent requests in a threaded SAPI.

### NixOS VM integration

Run the debug FPM lifecycle VM check on a Linux builder with KVM available:

```sh
nix build -L .#checks.x86_64-linux.php81-gcc-debug-vmtest
```

This target starts Nginx and a single FPM worker, then checks repeated requests and injected lifecycle failures using
[nix/vm-test/index.php](../../nix/vm-test/index.php). It does not rerun the full PHPT suite. The `php81-gcc-vmtest` and
`php85-gcc-vmtest` checks also run PHPTs inside the VM. The guest configures its own perf permissions. Host or nested
virtualization restrictions can still affect counter availability.

### Optional ASan/UBSan build

The sanitizer targets rebuild PHP with Perfidious built in, avoiding the dynamic extension loader's interaction with
ASan. Build the PHP executable or run its associated test target:

```sh
nix build -L .#sanitize-static-php82
nix build -L .#sanitize-static-php82-check
```

These targets are opt-in and are excluded from the normal Nix check matrix. The configure flag
`--enable-perfidious-sanitize` instruments the extension's objects with ASan and UBSan. The Nix target links the
sanitizer runtimes into PHP, but it does not instrument all PHP core code.

The check target sets `USE_ZEND_ALLOC=0`, supplies the sanitizer runtime environment, and uses an ordinary PHP binary
for stub reflection through `PERFIDIOUS_STUB_PHP`. LeakSanitizer is disabled in that target. Use the Valgrind checks
for leak testing, and inspect sanitizer test skips rather than assuming they match a shared-module build.
